Migration guide

Life after MineMeld

MineMeld's hosted service ended on 1 August 2021 and its open-source repositories were archived on 16 March 2023, still on Python 2.7. If you ran it to turn open threat feeds into firewall EDLs, Threat Feed Me does that job, on current software, in one container. This page is specific about what carries over and what doesn't yet.

Already on Cortex XSOAR? Its Threat Intel Management is Palo Alto Networks' own successor and has a node-by-node migration guide. Only need the SaaS allow-lists? Palo Alto's free EDL Hosting Service covers those today. Threat Feed Me is for the open-source, on-prem threat-feed pipeline.

Migrating PAN-OS EDLs

  1. Run it: docker run -d --name threat-feed-me -p 8080:8080 -v threatfeedme-data:/app/data alexlinos/threat-feed-me:latest. The first fetch of all 22 feeds takes one to three minutes; the dashboard's set-up guide shows progress.
  2. Swap the EDL source: in PAN-OS, Objects → External Dynamic Lists, edit each list that pointed at a MineMeld output and paste the matching URL: /feeds/high.txt, /feeds/medium.txt or /feeds/all.txt as an IP List, and /feeds/domains/… as a Domain List. Medium is the usual choice. If your model limits how many entries one list can hold, add ?limit=N to get only the N strongest, so the list fits instead of being cut off.
  3. Carry your whitelist over: the entries from your MineMeld whitelist nodes go in on the Indicators page (or POST /api/whitelist): IPs, CIDRs, domains or *.wildcards, everywhere or per tier.
  4. Bring your TAXII feeds: if your ISAC or TIP serves TAXII 2.1, add each collection as a feed (format TAXII 2.1 collection). TAXII 1.x sources need a 2.1 bridge.
  5. Point your SIEM at TAXII 2.1: the Connect view shows the discovery URL (/taxii2/).
  6. Check it's being pulled: each list URL on the dashboard shows when it was last polled and by what, so a typo in the EDL URL shows up as not polled yet instead of failing silently.

Questions

Is MineMeld still supported?
No. Palo Alto Networks ended the hosted MineMeld service in AutoFocus on 1 August 2021, and the open-source MineMeld repositories on GitHub were archived on 16 March 2023. The last release of minemeld-core was in April 2021, still on Python 2.7.
What did Palo Alto Networks recommend instead?
Cortex XSOAR Threat Intel Management, which has a node-by-node migration guide, and the free EDL Hosting Service for SaaS allow-lists such as Microsoft 365, Azure, AWS and Zoom.
Can Threat Feed Me replace my MineMeld threat-feed EDLs?
Yes, for the threat-feed pipeline: it pulls open threat feeds (including DShield and Spamhaus DROP, as MineMeld's default config did) and removes duplicates, then goes a step further. Feeds that republish each other count once, so one upstream list's mistake can't look like several feeds agreeing and land on the strictest list, while two unrelated feeds agreeing still moves an IP up. It applies your whitelist and serves plain EDL URLs that PAN-OS and other firewalls poll, and it also reads and serves TAXII 2.1.
Does it do the Office 365 and cloud IP-range lists MineMeld was used for?
Not yet. Allow-lists for Microsoft 365, AWS, Azure and Google Cloud are planned for version 2.6. Until then, Palo Alto's free EDL Hosting Service covers those.
Is Threat Feed Me free?
Yes. It is open source under the MIT licence and runs as one Docker container on your own hardware.
