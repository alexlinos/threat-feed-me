{# ======================= CONNECT (firewalls + integrations) ======================= #}

Connect

Firewalls poll the list URLs. UniFi and CrowdSec can't poll, so threat-feed-me pushes to them after every refresh. SIEMs and TIPs read the same lists over TAXII 2.1.

Firewalls and DNS filters: where each URL goes
  • FortiGate: Security Fabric → External Connectors → Create New → IP Address Threat Feed for IP URLs, Domain Name Threat Feed for domain URLs, then paste the URL. IP connectors are used as address objects in firewall policies. Domain connectors are used in DNS Filter profiles: Security Profiles → DNS Filter → the connector appears in the category table under the Threat Feeds group (top or bottom of the list depending on firmware) → set it to Redirect to Block Portal, then apply the profile to the policy carrying client DNS. Bonus: adding the IP connector under the same profile's External IP Block Lists also blocks lookups whose answers resolve to blocked IPs.
  • Sophos Firewall (SFOS 21.0+): Active threat response → Third-party threat feeds → Add → type IPv4 (or Domain), action Block, paste the URL.
  • SonicWall (SonicOS 7): Object → Match Objects → Dynamic External Object → protocol HTTPS, paste the URL; use the created address group in a rule.
  • Palo Alto: Objects → External Dynamic Lists → add as an IP List or Domain List.
  • Cisco Secure Firewall (FMC): Objects → Object Management → Security Intelligence → Network Lists and Feeds (IPs) / DNS Lists and Feeds (domains).
  • Check Point (R81+ SmartConsole): Security Policies → Threat Prevention → Custom Policy Tools → Indicators → New → External IOC Feed, paste the URL.
  • UniFi (UDM / UDM Pro / SE): can't poll a URL — use the UniFi integration panel below instead: it pushes the tier into network lists on the gateway after every refresh. Device limitations to know: lists cap ~10k entries and a policy can reference only ONE list (every firmware), so High = 1 list = 1 policy per direction, Medium = 4 lists, Everything = 10 — one policy each. Push High unless you enjoy policy bookkeeping.
  • pfSense (pfBlockerNG): Firewall → pfBlockerNG → IPv4 for IP URLs; DNSBL → DNSBL Groups for domain URLs.
  • OPNsense: Firewall → Aliases → URL Table (IPs); domain lists fit Unbound DNS block lists.
  • Pi-hole / AdGuard Home: add a domain URL as a blocklist (Adlists / DNS blocklists).
Lists are plain text, one entry per line, generated live with whitelisted entries removed automatically. IP URLs never contain a domain and domain URLs never contain an IP — an address-type feed import fed the wrong kind errors out on most firewalls. Most firewalls re-poll on their own schedule (e.g. every 5–60 min). Start with the Medium feeds. FortiGate note: external resources are capped per model (commonly ~131k entries / 10 MB); the domain Everything feed can exceed that, so point FortiGate DNS filters at the Medium or High domain feed. If a URL shows a loopback address, replace the host with this server's LAN IP or hostname.

{# CrowdSec, both directions (v2.5.0). Settings in a DB row; the machine login and bouncer key are write-only into the data-volume .env and bound to the LAPI (changing it clears them). Test is read-only. #}
CrowdSec integration: publish tiers to your bouncers, pull its decisions as feeds

Publish: after every refresh, the chosen IP tier is written into your CrowdSec Local API as ban decisions, so every CrowdSec bouncer you run (nginx, Traefik, Cloudflare, firewall) enforces it. On the CrowdSec host: cscli machines add threatfeedme --password '…' -f /dev/null, then enter that login under Set credentials. Each publish replaces the previous one with no gap; if threat-feed-me stops, its decisions expire after the duration.
Pull: cscli bouncers add threatfeedme and enter the key, then enable any of the crowdsec_* feeds under Feeds: your own detections, the community blocklist, and your subscribed lists each vote as a separate source. Decisions threat-feed-me published are never read back as votes.
Never publish into a honeypot's CrowdSec: a honeypot needs attackers to reach it. Pull from it; publish to the CrowdSec that protects your services.

{# UniFi push integration: UDMs can't poll a URL, so the app pushes the tier into firewall groups after every refresh. Everything managed here — settings in a DB row, credentials write-only into the data-volume .env (feed-API-key mechanics), Test = read-only. #}
UniFi integration: push IP tiers into UDM firewall groups

UniFi gateways can't poll a blocklist URL, so threat-feed-me pushes instead: after every refresh it maintains firewall groups named threatfeedme-<tier>-1..N on the gateway. Use a dedicated local-only UniFi admin restricted to the Network app.

The groups block nothing until you create policies referencing them (one-time step, after the first push):
· Current UniFi Network (zone-based firewall): Settings → Policy Table → Create Policy — External → Internal, action Block, Source = the threatfeedme-* objects; then a second policy Internal → External with Destination = the same objects (catches an infected host beaconing out). Enable logging on both to see hits in System Log / Flows.
· Older firmware (classic firewall): Settings → Firewall & Security → Firewall Rules — an Internet In / Drop rule with Source = the groups, and an Internet Out / Drop rule with Destination = the groups.
UniFi allows exactly one list per policy (every firmware), so each list needs its own policy per direction. List counts are FIXED per tier — High = 1, Medium = 4, Everything = 10 — with unused lists created empty up front, so the policies you build once stay complete as the corpus grows into them. High is the recommended tier for exactly this reason.
Domains can be pushed too (optional, no CyberSecure needed): set a Domains tier above and the push maintains Domain-type Network Lists named threatfeedme-dom-<tier>-1..N — reference them in a Block policy with Destination type Domain → List. Known UniFi UI quirk: the Policy Table's Destination column shows "–" for domain-list policies; open the policy to see the reference (it's saved and enforced). Alternatively a Pi-hole/AdGuard polling the domain feed URLs above does the same job off-gateway.
